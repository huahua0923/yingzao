# 建筑制图 / 实体建模 / 数字孪生 —— 知识图谱

> 目标：把「建筑制图国标 ＋ 高校资产测绘图实测约定 ＋ 实体建模对标」沉淀成**一张能查、能跑判据、
> 自己能发现漂移**的图，让遇到问题时**先查图**，而不是每次把当时的推理重跑一遍。

这不是一份文档库。它是**一台引擎 + N 个域**：一份装载格式（`kb.json`）、一个查询入口
（`ask.py`）、一个复核门禁（`gate.py`），域只是挂上去的知识。

## 为什么做

- 用户铁律：**「剖面和实际的图达到 95% 以上」「最终生成的是漂亮的建筑，不是乱七八糟的块体」**。
- 识别引擎曾靠几何启发式（墙=闭合双线、门=开口跨度、楼层=Y 聚类 gap）硬扛，缺一套
  「制图规范 → 识别规则」的正向映射。本图谱补这一层，并把它做成**可复核的边**。
- 资产图 DXF 由 ODA File Converter 转出，**不携带线宽/颜色/图层中文名**，
  因此不能直接套「粗实线=承重墙」的线宽语义，只能靠几何 + 图层数字前缀。

## 设计约束（护栏）

1. **只存边，不存值。** 图谱不抄 `DOOR_LEAF_MIN = 0.6`，只写边指向
   `backend/recognizer/component_library.py:DOOR_LEAF_MIN`；门禁去源文件把值读出来比。
   ⇒ 图谱是**发现漂移的尺子**，不是又一张会过期的表。
2. **不动生产代码。** `component_library.py` 只**引用**（`recognition[].related` 写 `文件:符号`），
   不搬不改。
3. **一个事实一份写法。** `title`/`slug` 由 `build_kb.py` 从 md 的 H1 推，`manifest.json`
   **不许写**；写了两处，改一处必漂。
4. **证据必须全仓解析得来，不许按文件名猜。** 记「解析出来的位置」，不记「推断的位置」。
   只查一个文件的门禁会**造出**假红。
5. **查不到就说查不到。** 症状不在图里时回「图里没有」＋ 最接近的几条，**绝不回空数组**
   —— 空数组会被读成「没问题」。

**不认 `--help`。** 本仓脚本靠 `sys.argv` 手解析，`--help` 会被当成参数值静默按默认全量执行。
探用法只读源码。

## 关键结论速查

- **线宽组** b : 0.5b : 0.25b（粗:中:细 = 4:2:1），2010 版细分中粗 0.7b。
- **粗实线** = 剖切到的主要构造（承重墙/柱断面）；**中实线** = 次要构造（墙身/台阶/门扇开启线）；**细实线** = 尺寸/图例/窗轮廓。
- **点划线(细)** = 定位轴线/中心线；**中粗虚线** = 不可见轮廓/拟建建筑。
- **剖面材料**：砼/钢筋混凝土断面小 → **涂黑**；砖 → **45° 斜线**；未注明材料 → **45° 细实线**；相邻涂黑间隙 ≥0.7mm。
  ★识别上的主要价值是**负例**：大面积涂黑/斜线是楼板填充，不是墙。
- **门窗**：门代号 M、窗代号 C；门开启弧 45°/90°、实线外开/虚线内开；窗=双线+玻璃线。
  ★**门 = 墙的缺口，不是洞**；**窗是合成数据**，不从图读。
- **楼梯**：踏步线每格一级、折断线 45°、「上/下」长箭头、梯段边双线=栏杆。
  ★两道判据缺一就出假井（段数 + 纵向跨度 ≥1.5m）；楼梯井是**跨层量**。
- **资产图坑**（见 `src/07`）：层名乱码、中文编码混杂(GBK/UTF-8)、门=INSERT 块、墙=LINE/LWPOLYLINE 两套。
  ★『层名撒谎』有 8 栋例外，登记在 `LAYER_ROLE_OVERRIDE`，不许靠层名猜语义。

## 门禁怎么用（`kb/gate.py`）

```bash
python -u kb/gate.py              # 复核全部边；有红则退出码 1
python -u kb/gate.py --selftest   # 十一条刑具，每条都要能红（只验「干净时绿的」等于没验）
python -u kb/gate.py --record     # 重建 evidence-lock.json（证据文件内容指纹基线）
python -u kb/gate.py --json
```

**八条判据**（编号 ①–⑦ ＋ ⑪）：①路径可达 ②行号在范围 ③符号真在（**AST，不许 grep**）
④值漂移（委派 `values.py`）⑤图层语义双源一致 ⑥**陈旧即红**（按内容 sha12，不按 mtime）
⑦`--run` 白名单必须只读 ⑪**ASCII 引号被当中文引号用**（铁律 15）。

★ **编号从 ⑦ 跳到 ⑪ 是有意的**：⑧⑨⑩ 是**刑具组**的号（⑧陷阱分两栏 ⑨手册三栏
⑩re-baseline 的差异报告），不是第几条判据 —— 保持原号是为了不与既往记录对不上。
★ **陷阱不是第八条判据**，它是**边的第二个来源**：`traps.json` 的 `cases[].where` 与
`kb.json` 的 evidence 走**同一套** ①②③；唯一多出来的是**分栏** —— **有锚点的**并入上面的边，
**没锚点的**（`unverifiable`）单列出来数。`traps.json` 不在盘上 ⇒ 这一类是**没被查过**，
不是「没有陷阱」（同 `UNAVAILABLE ≠ PASS`）。

★ **⑪ 为什么值一条门禁**：这个缺陷**在屏幕上看不出来** —— `"` 和 `「」` 在编辑器里几乎一样。
而它写进代码行时，Python 看见的是夹在中间的**裸标识符** ⇒ `SyntaxError`，报错还指不到真正的原因。
规格分三档，**不是**图省事，是因为「引号在这类文件里能干什么」不同：

| 档 | 文件 | 判据 | 为什么这样定 |
|---|---|---|---|
| 严 | `kb/*.py` | 引号**两侧都是汉字** | 正常定界符左边是 `(`/`,`/`=`/空格，绝不会夹在汉字中间 ⇒ `x = "汉字"` 不误伤，只有**写错的**命中 |
| 宽 | `kb/**/*.md` | **任一侧**是 CJK（先掩掉围栏与 `行内跨度`） | md 不会被解释成语法，宽了不误伤代码；实测漏网形态恰是 `把"C4 是 gap"的红快照`（一侧夹拉丁词，严档看不见） |
| — | `kb/*.json` | 只要求**能解析** | 值里的中文引号与 md 同源，套规则 = 一条缺陷报两次 |

⇒ 宽的代价是一条**约定**：md 里的命令/代码必须写进反引号跨度（现有文档都是这么写的）。
★ **分母写在输出里**：`只量 kb/ 内的自有文件` —— 仓内其他文件**一次都没量过**，
「没量过」和「干净」在屏幕上必须不是同一行字。

★ **边界为什么划在 `kb/`**：这一档只对**会被工具解析的东西**有意义 —— `kb/src/*.md` 装进
`kb.json` 的 `content` 被 `ask.py` 当结构返回，写错就是**机器读到的东西坏了**。
而 `CLAUDE.md`、`docs/*.md` 这类**指令/说明文件**不被任何工具解析，ASCII 引号在那里
只是文风问题 ⇒ 不套此规则（实测 `CLAUDE.md` 全文有 120 行是这个写法，是它一贯的风格）。
**不套 ≠ 干净**，是**不量**：两者的区别就写在这两段里。

**为什么 ⑧ 要点名那两条「只有人记着」**：一条陷阱没有仓内锚点 ⇒ 它不可复核、会随人走。
把「陷阱全部有据」印出来（不写分母），就是把「只有人记着」抹平成了合格 —— 与
「`UNAVAILABLE` 被读成 `PASS`」是同一条错。

★ **② 的边界（实测）**：`file:74` 只核「第 74 行**存在**」，**不核「那行还是那句话」**。
本文件往上补了几行之后，`:74` 指的东西全变了，而 ② 照样绿 —— 抓住它的是 ⑥（内容指纹）。
所以**行号锚点必须与内容指纹配对用**，这正是 `evidence-lock.json` 存在的理由。

| 问题 | 从哪看 | 2026-09-24 快照 |

| 一共核了多少条边 | `① ② ③ 边本身：N 条` | **249**（PASS 244 ／ N/A 5） |

| 陷阱登记了几条 | `◇ 陷阱：登记 N 条` | 19（可核边 57 = 实物锚点 35 ＋ 关联 22；**只有人记着 2 条**） |
| 别名表覆盖多少叫法 | `build_kb.py` 的输出 | **612**（★家族的 `symptoms/causes/fixes` 的 `what` 文本**本身就是别名键**，见 `build_kb.py:222-225` ⇒ 加一条 cause 就会 +1，属构造使然） |
| 手册有几个家族、几条边 | `◆ 手册：` 那一行 | 12 个家族；可核边 132；**缺 evidence 0**（缺陷） |
| 有多少条只有人记着、仓内无锚点 | `◇ … 声明无锚点` / `**只有人记着**` | 手册 9 条；陷阱 2 条（分开数，不许合并） |
| 智能体允许跑几条命令 | `⑦ --run 只读：待登记命令 N 条` | 12（全部只读；`--apply`/`-o` 一律拒登） |
| 排队等人收的症状几条 | `kb/pending.json` 的条数 | **0**（＝ 还没有人报过，**不等于**「没有未收录的症状」） |
| 实例层覆盖多少楼·层 | `derive.py --check` 那一行 | **95 栋 = 49 有机器产物 ＋ 46 UNAVAILABLE**；缺陷 **2512** 行 = 已映射 2512 ＋ 未映射 **0**；flags 64 处 = 命中 52 ＋ 未命中 12；跨层行 13 |

★ **上面这一格是今天唯一一个「从坏数变成好数」的**：2512 行原先只有 54 行进得了图
（识别侧的计算写在「有报告」分支里），修掉后 21 个 code **全部映射**，未映射归零 ——
但归零**不等于**没有缺口：仍有 **12 处** `墙占比>0.35` 的 flag 点不到任何家族，
它们被数在 `flags 未命中 12` 那一格里。**两个数都要印出来**。

★ **这张表是快照，不是真值** —— 它是「某时刻某把尺子量出来的」。要现值只有一个做法：
   跑它左栏那句命令。抄进来的数**一定会过期**，而且过期之后**看不出来**
   （本行原先写 99 条 / 331 别名 / 队列 3 条，twin 域进来之后三个数全错了；
   2026-09-24 又实测一次：这一版先写 135 条，**同一小时内**补了两条陷阱案例就变 137；
   **同一天第三次**：把 4 个家族用 `--run` 过了一遍、按产物改了两条 `expect`、补了 3 条
   `related` 与 2 个陷阱 case ⇒ 137 变 **141**、手册可核边 37 变 **39**；
   **紧接着第四次**：拿交付件实测复核 `room-outside-outline`（全库 137 个多块层、0 层
   回退生效）、把「旧版静默退回」改写成「这一支已出声」、补 1 条 cause ＋ 1 条 related
   ⇒ 141 变 **144**、手册可核边 39 变 **41**；
   **同一天第五次**：把家族按同一形状从 4 个扩到 **12 个**、补 2 条陷阱、
   把 21 个 code 全部接进家族 ⇒ 144 变 **241**、别名 413 变 **588**、
   手册可核边 41 变 **132**、命令 4 变 **12**；
   **同一天第六次（本次）**：修「尺子指纹报错制品」与「产物不可复现」两个缺陷，
   顺手把它们登记成陷阱 ⇒ 241 变 **249**、别名 588 变 **612**、陷阱 17 变 **19** ——
   六次全是「抄完就变」，抄数的人不会有第二次机会，所以别抄）。
   ⇒ 所以「从哪看」那一栏才是这张表的主体，「快照」那一栏只是给人一个量级感。

★ 「边全绿」这句话**只有配上分母和 N/A 才成立**。没有分母的绿勾，和「没量过」长得一样。
★ 「缺 evidence 0」是**缺陷数**，它必须永远是 0；「声明无锚点 9」是**诚实数**，它不必是 0 ——
两个数放在一起看才有意义，合并成一个数就两件事都说不清了。
★ **但「声明无锚点」这一栏自己也会膨胀**：从 3 条长到 9 条，是因为家族从 4 个扩到 12 个，
   每一族都**至少**留下一条「这条我知道，但仓内指不出来」。它涨得比「有锚点」快是对的 ——
   **先诚实登记缺口，再慢慢补锚点**，比反过来（先写漂亮话，缺口不登记）安全得多。
   实测那 9 条里有一条正是这种情况：`criterion-crashed` 的「c009 的轮廓为什么成了 MultiPolygon」
   —— 本轮只确认了「现在跑会崩」和**崩在哪一行**，没核过是哪次改动造成的，就写成 unverified，
   不编一个像样的理由。

## 家族清单（快照 · 现值看 `ask.py --list`）

## 引用 `_qa/<楼>_qa.txt` 之前必须知道的两条

`_qa/` 下那 60 来份逐楼报告是图谱**最常用**的证据来源（`instances[]` 大多指它），
但它们有两条性质，任一条忽略都会把「读到的」当成「现在的」：

**① 报告是**按严重度过滤过的**，而且写到一半崩了就不写。**
`[WARN]` 行在，`sev=INFO` 的行**会被过滤掉** —— 所以「报告里没有这条」≠「这件事没发生」。
2026-09-24 实测最锋利的一例：`c009` 由 `qa_structural.py` 跑到 I1 时抛
`AttributeError: 'MultiPolygon' object has no attribute 'exterior'`（轮廓成了多块多边形），
**整栋就此中断** —— 而 I1 是第一条判据，I2…I18 **一条都没跑**。
后果不是「报错」，是**屏幕上什么都不出**：报告写不出来（崩在写盘之前），
`_qa/defects.json` 里只留**一行** `code=QA, sev=INFO`、
`msg=AttributeError: …'MultiPolygon'… exterior`、`floor=null`（所以它落 `_cross_floor` 桶，
**不属于任何一层**）。★ 于是「0 行」和「干净」长得一模一样，已单独立成一族
`criterion-crashed`：**别改 `qa_structural.py`**（用户明令），改法是**先读 `code=QA` 那几行**，
再决定这个「0」能不能信。
★ 盘上那份 `_qa/c009_qa.txt` 是 9-15 的旧产物，看着完整、有 5 层 bbox 和一堆 I1 行 ——
**它不会告诉你今天跑会崩**。要相信一个报告，得先问「它是哪次跑出来的」。

**② 报告会被重跑整体覆盖 —— 所以别拿行号指它。**
`_qa/<楼>_qa.txt` 每次重跑都是整篇重写（多一层楼就多一行 bbox），行号随之移动。
2026-09-24 就有一条边指到了覆盖后的**空行**（见「行锚点会漂」那一段），
修法是把锚点改指**归档副本** `_qa/_archive_qa_txt_20260924/`（61 份，重跑前留档）。
★ 通则：**引用一个会被重新生成的产物时，指它的归档副本，或指产生它的代码**；
活动产物只配「当次读数」。

## 尺子指纹：三个版本号，各有其主（2026-09-24 修）

**症状**：`ask.py` 的 `ruler` 块过去只有一个 `criterion_version`，报出来永远是 `1`
—— 当天手册语义刚从 **v3 改到 v4**（家族 4 → 12），**这个数一动不动**。
于是它答不了它被派去回答的那个问题：「这份数是哪把尺子量的」（铁律 24）。

**根因**：`criterion_version` 这一个名字在本仓有**三个**出处 ——
打包器 `kb/build_kb.py:CRITERION_VERSION`、手册 `kb/playbook.json`、陷阱表 `kb/traps.json`。
产物只装了**打包器**那一个。手写版本号的作用是「说清语义变了什么」，机械 sha12 的作用是
「说变了」—— 被丢掉的恰好是**手写那一半**，而且**丢掉这件事不报错**：字段在、类型对、量级合理。

**修法**（三处，各一层）：

| 层 | 动作 |
|---|---|
| 打包 | `build_kb.py:_hand_meta()` 把两个源手册**自己声明**的版本带进产物：`playbook_criterion_version` / `traps_criterion_version` |
| 出口 | `ask.py:ruler()` 三个都报，并且**名字里点明属于谁** —— 那句话**也取自产物**（`criterion_version_means`，打包器写的），出口只透传 |
| 后台面 | `backend/api/services/kg.py:_ruler()` 报**同样四个字段**（键名逐字相同）；`kg.js` 分三处印：`打包器 v1 · 手册 v4 · 陷阱 v5`，不再印一个裸 `criterion v1` |
| 判据 | `--check` 的比对键表加上这三项 ⇒ 源上把 v4 改成 v5，`--check` **指名**报 `playbook_criterion_version: 4 → 5` |

★ 同一个改动里附带一条**别混为一谈**的：`dropped_keys`（源手册里哪些顶层键没进产物，机械算出来）。
它查的是「**键**有没有进产物」，而上面这个缺陷**恰好抓不到** —— `criterion_version` 那个键一直在，
只是装的是**另一个制品**的值。**「键在」不等于「值在」。** 它防的是将来：源里新加一个键不许无声蒸发。

★ 这条的验收**四个方向都要**（`_scratch/_rd2_falsify_hand_version.py`，一次性探针）：
值真的走到出口 ／ 改源 `--check` 指名报出 ／ 重建后**出口报的数跟着动** ／
逐字节还原且 kb.json 回到**同一 sha256**（做过的事不留痕）。
其中第三条是**这个缺陷本身**：只验前两条的话，字段恒为 `None` 也能被 `_diff` 报成「None → 5」，
判据是绿的而病还在。

★ **后台面的那一份已经改成透传**（同日补）：过去 `backend/api/services/kg.py:_ruler()`
独立读 `kb.get("criterion_version")`，于是后台页只印打包器那一版（`criterion v1`）——
**同一个判断两份实现**，迟早同屏两句话。现在它报**同样四个字段**、键名与 `ask.py:ruler()`
逐字相同，那句话也取自产物；`kg.js` 分三处印名。
★ **还剩的不是代码，是进程**：跑着的后端要**重启**才拿到新代码。实测（2026-09-24）
`127.0.0.1:8153` 的 `/api/kg` 仍回 `playbook_criterion_version: None` ——
**它读的是新产物（三个字段都在里面），跑的是旧代码**：这正是「产物不是源码」那一档，
和铁律 25（改 `src/` 不 build ⇒ 线上照旧）同形，只是这里换成了「不 restart」。
⇒ 判据：拿**监听端口的那个进程**回的东西为准，别拿盘上的文件当结论。

★ **新加的 T10** 守着上面这句话的**键集合**：`criterion_version_means` 的键必须与它解释的
三个字段逐一对上（字段改名而说明书没跟着改 ⇒ 红）。它自己带**三个坏样本**
（多一个键／少一个键／值只剩空白），所以「这条能红」是被证明过的，不是声称的。

## 产物必须逐字节可复现（2026-09-24 修）

**症状**：同一份源连build三次，得到**三个**不同的 sha12 —— 解析后逐键相同、
连字节长度都一样，只有**键序**不同。

**根因**：`build_kb.py:_index()` 直接遍历 `set`。字符串集合的迭代顺序随进程的哈希种子变
（Python 的 hash randomization），于是 JSON 里**键的插入顺序**跟着变。
后果不是「难看」，是**指纹失效**：`sources` / `generated_from` 里 kb.json 的 sha12 每次重建都变
⇒ 下游「源的内容指纹变了」那类判据（`derive.py` 腿②、门禁⑥、证据锁）
**分不清「源真的改了」还是「只是重建了一次」**。判据天天红、每次都红在假的地方，
结局就是没人再看它（同族：`trap-in-progress-read-as-final` —— 数是真的，但答不了那个问题）。

**修法**：`_index` 里三处取词一律 `sorted(...)`，并在 docstring 里写明
「这里是**唯一**决定词序的地方，与哈希种子无关」。
判据 `--selftest` 的 **T9**：起**子进程**、换 `PYTHONHASHSEED` 比字节
（★ 在同一个进程里比两次是**恒绿**的，因为种子相同 —— 写成那样就是摆设），
并配阴性对照：两个种子下 `hash()` 必须**不同**，否则上面那条比较已经成了恒绿，对照会红着把它指出来。

★★ **T9 自己的阳性对照，我第一版写错了，记在这里**：我在子进程里打
`build_kb.sorted = lambda it: it`，本意是「拆掉 `_index` 的排序」，实际把**整个模块**的 `sorted`
都拆了 —— `_hand_meta` 那边 `sorted(k for k in …)` 返回了个 **generator**，json 当场 TypeError，
**两个子进程都崩、都吐 0 字节**，而 `0 == 0` 在我的屏幕上长得就像「没差异」，差点据此写下
「拆掉排序它仍不红 ⇒ 这条刑具是空的」。
**正确的做法是只改一个变量**：把 `build_kb.py` 抄一份到 `kb/` 下、只拆 `_index` 那三处 `sorted`
（**写盘前数出「恰好 3 行不同」**，自证作用域），跑完删掉、删干净落到退出码上
（`_scratch/_rd3_control_t9_can_red.py`）。它给了正确结论：拆掉排序后，两种子立刻产出不同字节
⇒ T9 抓的正是这一档。
★ 两条并记：**空输出不是「没有差异」**（铁律 16）；**一条拆不掉的判据等于没有**（铁律 26）。

★★ **同日第三次踩同一族：探针的红也要能解释「它红在哪一步」**（2026-09-24 当天）。
T10 落地后再跑 `_rd2_falsify_hand_version.py`，④ 报红：「还原并重建后 kb.json 与实验前不同」，
第一处差异是 `"self_sha12": "95bfc405e668"` vs `"c421ec935c63"`。看着像**产物不可复现**又犯了 ——
真因是**我拿来当基线的那份已经陈旧**：我改完 `build_kb.py`（加 T10）之后**没有重建 kb.json**，
盘上那份里的 `self_sha12` 还指着上一版生成器；探针的重建是**忠实**的，它把当前的写了出来。
`self_sha12` 就是 `sha12(build_kb.py)`（机械指纹，实测逐字节相同），所以这个差是**生成器的差**，
不是产物的漂移。
⇒ **判据**（两个方向都量过，别推理）：把产物里的 `self_sha12` 改成假值 ⇒ `--check` **红且指名**
`self_sha12 变了（源码/清单/尺子动过）`；还原成同一份字节 ⇒ 绿。也就是说「生成器改了、产物没重建」
这一档 `--check` **看得见**（`self_sha12` 在 `_diff` 的比对键里），不存在盲区。
⇒ 通则：**「判据红了」和「被测对象坏了」之间还隔着一步 ——「我拿来比的那份是此刻的吗」**
（铁律 22 的镜像：那边是「进行中的数被当终值」，这边是「过期的数被当基线」）。
换了生成器/尺子，**先重建产物再当基线**。

## 智能体流程（本图谱的**唯一**消费者是智能体）

图谱不是给人看的文档，是**智能体遇到问题时的第一步**。所以形状按「智能体怎么用」定：

```bash
python -u kb/ask.py "楼层错位" --json     # ★主接口：机器可执行的结构，不是散文
python -u kb/ask.py "c057 楼层错位"       # 人看的排版（附带）；带楼名 ⇒ 实例先挑该楼的
python -u kb/ask.py "楼层错位" --run      # 真去跑图里登记的那条只读判据，并留痕
python -u kb/ask.py --list                # 已知症状 / 陷阱 / 知识条目（含「只有人记着」那栏）
python -u kb/ask.py "洞中洞" --pending --who 智能体A   # 把查不到的症状登记进队列
python -u kb/ask.py "洞中洞" --pending --dry-run        # ★问「会不会被接受」，不写盘（验收用这个）
python -u kb/ask.py --selftest            # 刑具清单**以输出里那串枚举为准**（此处不写数 —— 见下）
python -u kb/ask_falsifier.py             # ★--selftest 自己的阳性对照（6 处改坏都要红）
python -u kb/gate.py --anchors            # ★每条锚点「此刻指到什么内容」（改完文档必看一眼）
python -u kb/gate.py --record             # 重新登记基线；★会列出变动的文件＋指进去的锚点
python -m backend.checks.kg_view_accept --parity --base http://127.0.0.1:8153   # ★K5 验收（见末节）
```

★ **「--selftest 有 11 组刑具」这句话本身就该被删掉。** 输出的第一行是「刑具全部能红 ——」
后面跟着**枚举**（`miss` 不空回／`unverified` 与 `hit` 分开／单字别名不许凭子串点亮／…），
那就**是一份全文清单**；在文档里再写一个数，等于同一个事实两处写法 —— 它必漂，而且
**漂了看不出来**（今天刚为此记了一条陷阱 `trap-hardcoded-count-in-output`：
`derive.py` 的汇总行里印着写死的「16 个 code」，而真值是 21，同一行另外两个数却是实时算的）。
⇒ 规矩：**屏幕上的每个数都必须是算出来的；说明文字里不写数，写「以输出为准」。**

★ **验收/自检登记症状，务必把队列改道** —— 而且**这件事现在是代码在管，不是靠记着**。
  `kb/pending.json` 是「等人来收」的**生产**队列，`--pending` 一跑就往里追加 ——
  验收跑一遍就多几条模拟记录，`who` 还写着「智能体A」，**跟真的上报长得一模一样**
  （实测：K2/K5 验收塞了 4 条，事后只能靠时间戳认出来）。
  ⇒ 三条出路，按优先：
  1. **`--dry-run`：问一句「会被接受还是会被拒」，一个字节都不写。**
     `python -u kb/ask.py "洞中洞" --pending --dry-run --who 现场巡检`（退出码 0=会接受 / 2=会拒）
     ★ 为什么必须有它：验「真署名不该被误拒」那一侧，唯一的笨办法就是真写一次 ——
     而那次写入**会留在生产队列里**（实测：验完队列里躺着一行测试记录）。守卫拦不住它，
     因为它长得就是一条真记录；守卫按设计只能拦「自称是模拟」的那种。
  2. **改道**：`GYM3D_KB_PENDING=<临时文件> python -u kb/ask.py "…" --pending --who 验收`。
  3. **守卫兜底**：`who` 里出现「验收/自检/模拟/测试/selftest/fixture」时，
     打生产队列会被**直接拒**（退出码 2）并告诉你怎么改道。卡在 `append_pending` ——
     **写入口唯一**，所以下一个调用者也绕不过去。
  ⇒ 不设这个变量时行为一个字都没变（默认仍是那份生产件）。
  ★ 守卫要能红才算数：`--selftest` 的 T7c **必须开子进程**才量得到它 ——
    `PENDING` 在 import 时定值，进程内改不动，所以「改道之后还能不能写」这一面
    在同一个进程里**不可观测**（不设变量时错的写法与对的写法表现完全一样）。
    第一版守卫就是这么错的：它拿 `path == PENDING` 当「这是生产队列」，
    于是**一改道，任何目标都成了生产队列**，验收永远写不进去 —— 而自检那一格是**绿的**。

★ **行锚点会漂，符号锚点不会。** `file:128` 只能证明「第 128 行存在」—— 文件里**加两行**，
它指的就换了一句话，而 ①②③ 全绿。本仓栽过一次（实测）：往本文件顶部加了 2 行，
`kb/README.md:78` 从「护栏 1 只存边不存值」变成「## 设计约束（护栏）」这个**标题**、
`:85` 从「护栏 4」变成「护栏 3」，两处**都还在**行内，门禁一声没吭。
★ **第二次（同日，更毒的一档）：锚点指的文件整个被重跑覆盖了。**
`pb:column-and-slab-support.instances[1]` 指 `_qa/c001_qa.txt:8` —— 那句话是
「f0 柱在自身轮廓外 0.6m @(-9.10, **-13.22**)」。当天 `_qa/` 那批报告被重跑覆盖：
行数 139 → 131、**第 8 行成了空行**（原话挪到第 9 行）、柱的 y 变成 -16.20、
三个码的计数也全变了（I2 103→89 / I1 12→17 / I10 1→2）。
而这条边 **①②③ 一直全绿** —— ② 只问「第 8 行存在吗」，**存在，它是个空行**。
抓住它的是 `--record` 的**锚点视图**：重登记时逐条打出「此刻指到什么」，
那 12 行里 11 行是符号锚点（一字未变）、**第 12 行是行锚点，箭头后面是空的**。
⇒ 已改指**归档副本** `_qa/_archive_qa_txt_20260924/c001_qa.txt:8`（61 份重跑前留档），
并把原话与两个版本的数字**都写进那条 claim** —— 「旧值是什么」和「现在是多少」是两件事，
只留后者会让下一次读的人以为什么都没发生过。已记成陷阱 `trap-line-anchor-in-regenerated-product`。

⇒ 四条对策，按优先：① 能上符号锚点就上（`kb/*.py` 一律 `文件:符号` —— 指进 `kb/gate.py`
的锚点全是符号形，`--anchors` 可现场核）；② **别把行锚点指进「会被重跑的产物」**（`_qa/<楼>_qa.txt`、
`_qa/defects.json`、`data/_meta/*.json`、任何汇总）—— 要么指归档副本，要么指**产生它的代码**；
③ markdown 没有符号可锚（`ast` 解析不了），所以每次改完**跑一遍 `--anchors` 肉眼核**；
④ `--record` 会把「变动的文件 ＋ 指进它的锚点**现在指到什么**」打出来 ——
re-baseline 因此从「一句『已登记 28 个』把错位默默洗掉」变成一次**定向复核**，
而且**必须读**：只比指纹的话，屏幕上是「3 个文件变了」，签个字就过去了，
**指错的地方一个字都不会露出来**。

**① 三态必须分开**：`state` ∈ `hit`（图里有）／`unverified`（图里记着、但没仓内锚点）／
`miss`（图里没有）。`miss` **不许回空数组** —— 回「图里没有」＋最近似的 3 条＋登记入口＋
**这个说法此前被登记过几次**。「图里没有」和「没问题」在屏幕上一模一样，
而智能体会把空数组当成「没这回事」。

★ 命中还要再分一档 `hit_kind` ∈ `family`（手册家族，**有可跑判据**）／`trap`（陷阱）／
`entry`（只是一篇域知识，**没有判据**）—— 智能体据此决定是「去跑」还是「去读」。
「读到了」不等于「验过了」，这两件事在输出里必须占两个值。
★ 三态与 `hit_kind` 都不许由**单字子串**点亮（实测：「漏墙」在没有家族时被单字「墙」
带得 `hit` 到一篇无关文档）；单字别名只认精确命中。

**② 每条命中都带 `next_action`**：下一步跑哪条判据、期望什么结果、读哪个字段。
判据命令**只从图里来**（门禁⑦已验只读），智能体不许自己现编命令。
★ `ask.py` 里**没有任何一个口子**能把命令当参数传进来；跑的时候也**不经过 shell**
（`argv_of` 只收纯 argv 形，含 `; & | < > $ \` * ?` 等元字符即**拒跑**并留痕）——
图谱是个文件，`shell=True` 会让文件里的一行变成一次注入。
★ 「跑不起来」（`NOTFOUND`）与「跑完了没输出」必须是两个退出值，不许长得一样。

**③ 回写协议 —— 「智能体的判断沉淀回引擎」的机械形态**

| 步 | 动作 | 卡在哪 |
|---|---|---|
| 1 | 新症状/根因/处置/判据 → 落 `playbook.json` 的**固定字段** | 字段表写死，不许自造字段 |
| 2 | 每条边必须带 `evidence`（`file:行` 或 `file:符号`） | ★ **门禁核不过就不许进图**（不是「建议带」） |
| 3 | 进图后跑 `gate.py` ＋ `build_kb.py --check` ＋ `gate.py --record` | **三个都绿**才算收进去 |
| 4 | 只来自实战、仓内确实无锚点的 | 落 `playbook.json` 的 `unverified[]` 或 `traps.json` 的 `unverifiable` |

第 4 步不是「跳过检查」，是**换一个栏位登记**，而且那个栏位会被门禁⑧**数出来**。
「有据」与「只有人记着」在输出里必须占两个格子。

**④ 查不到的症状登记到 `kb/pending.json`**（谁／何时／什么症状／最像哪一条）。
把「下次还得猜一遍」变成「排队等人收」 —— 猜和排队在屏幕上必须不是同一件事。
★ 空文件 = **还没有人报过**，不等于「没有未收录的症状」。
★ **排队 ≠ 已认识**：队列不会被 `ask.py` 当知识读，同一个说法在落进 `playbook.json`
之前照样回 `miss`，而 `miss` 的返回里会写「已被登记 N 次」——
不然读者会以为「我登记了怎么还查不到」，然后开始怀疑图谱坏了。
★ 同说法**重复登记照样追加，不去重**：重复次数本身就是「这个症状有多常见」的证据。

**⑤ 判据结果留痕**：`--run` 跑过的判据把 `(命令, 退出码, 关键输出, 时刻, 尺子指纹)` 落
`data/_meta/kg_runs.json`。★ 带**尺子指纹**，否则下次读到的数分不清是哪把尺子量的。
★ 指纹是**四项**：`criterion_version`（手写）／`kb_self_sha12`（**生成器** `build_kb.py` 的 sha12）／
`gate_sha12`／`playbook_sha12`（**手册内容**的 sha12）。前三项**都盖不住「手册改了」**——
要跑哪条命令、该期待什么，全是 `playbook.json` 决定的；少了第四项，改完手册之后
旧条目会看起来仍然现行（这正是铁律 24 那一档：产物不说是哪把尺子量的）。

**⑥ 分工**：子智能体（采收／复核）**只读 ＋ 产出结构化候选**；**写入只有一条路径**
（专用 writer ＋ 门禁卡在写入口）。子智能体直接写盘 ⇒ 门禁形同虚设。

**⑦ 实例层：机器派生的「症状 ──观察于──▶ 楼栋·层」**（`kb/derive.py` → `data/_meta/kg_instances.json`）

手工记的症状是**知识**，机器量的实例是**本次实测**。合成一个数组就再也分不清这两件事，
所以 `ask.py` 把它们分成 `instances`（手工）与 `derived_instances`（机器）两栏摆。

```bash
python -u kb/derive.py             # 派生并落 data/_meta/kg_instances.json（原子写）
python -u kb/derive.py --check     # ★只读复核：与源逐条计数不同即退出 1
python -u kb/derive.py --selftest  # 7 组对照，三条腿各自单独断言（含 1 组阴性对照）
```

★ **两个轴，不是两份副本。** `_qa/defects.json`（识别/台账侧，**2512 行**、21 个 code）与
`_qa/defect_<楼>.json` 的 `rows[]`（几何侧逐层实测，**49 栋**）**键完全不同、行数也不同**
—— 它们是**两把尺子**，所以分栏成 `by_code` / `by_flag`，并把**两边都命中**的楼单列
`both`（那才是互相印证的那一档）。合并成一个数就再也分不清是哪把尺子量的。

★ **两把尺子不许互相挡门（2026-09-24 实测修掉的一处静默丢数）。** 识别侧覆盖 **95 栋**、
几何侧只有 **49 栋**，而代码里曾把 `if 楼.report is not True: continue` 写在两轴之间 ——
等于**拿几何侧的门票去挡识别侧的数据**：9 栋（c001/c003/c007/c021/c023/c110/c112/c113/m282）
的 **10 条家族命中静默不进实例栏**，而屏幕上与「一处也没观察到」长得**一模一样**。
现在：code 轴只看有没有 code，flag 轴只看有没有 obs；缺几何侧的楼单列进
`by_code_geometry_unmeasured`（**「几何侧没量过」≠「合格」，也≠「两边印证」**），
并由 `ask.py --selftest` 的 **T9b 合成稿**双侧断言（无报告那栋必须**在** `by_code`、
必须**在** unmeasured 栏；有报告那栋必须**不在**）。同一处缺陷在 `kb/derive.py` 也有过一份
（识别侧的计算写在「有报告」分支里 ⇒ 2512 行只有 928 行进得了图），是腿③
「逐条计数不同」当场抓出来的 —— **断言比人先看见**。

★ **没对上的必须被数出来。** 原先 16 个 code 里只有 3 个（D1/D7/I3）能对上家族 ⇒ **2458 行**
落进 `unmapped`。**那不是「没有缺陷」，是「图谱里还没有这个家族」** ——
所以本轮做的事就是**把家族按同一形状扩到 12 个**，直到 21 个 code **全部映射**（未映射 0）。
而 flag 轴还剩 **12 处**（`墙占比>0.35`）点不到任何家族，照样被计数。
⇒ 两个数必须分开印：**code 轴未映射 0** 是「这一轴接完了」，**flag 轴未命中 12** 是
「这一轴还有一个家族没建」—— 合并成一个数就两件事都说不清
（同「缺 evidence 0」与「声明无锚点 9」必须分两个格子数）。

★ **跨层行不是任何一层。** 源里 `floor=null` 的 13 行（跨层重复房号／整栋汇总行／层号哨兵
`[-1]`）落 `_cross_floor` 桶：写成 `0` 会凭空造出「F0 有 13 个缺陷」，写成 `-1` 会造出假楼层 F-1。

★ **`UNAVAILABLE` 是一座楼一行，不许消失。** 95 个交付目录里 49 个有机器产物，
其余 **46 个在实例层里是带 reason 的 `UNAVAILABLE` 行** —— 「没量过」不是「合格」。
`ask.py` 那条路径同样：实例稿缺失时回 `UNAVAILABLE` ＋ 补救命令，**绝不回「0 栋」**。

★ **三条腿，各配一条只有它能看见的对照**（多腿判据最怕退化成「红了就算过」）：

| 腿 | 比什么 | 只有它能看见的 |
|---|---|---|
| ① 重算比内容 | doc vs 按当前源重算 | 产物陈旧／被改过（**指名到叶子字段**，不是「某棵子树不一致」） |
| ② 源内容指纹 | 每个源的 sha12 | **条数一个没变而内容变了** |
| ③ 逐条计数 | 直接数源列表 vs doc 的分组 | 分组写错、跨层行被当成某一层 |

★ 实例是**快照**：源一改就得重跑 `derive.py`。`ask.py` 的返回里带 `ruler_of_instances`
（derive.py 自指纹 ＋ 每个源的内容指纹），就是用来回答「**这份数是哪把尺子量的**」。

## ⑧ 图谱红了会出现在总表里（C4）

图谱自己的门禁很强，但它**靠自己不会被执行** —— 「闸门存在 ≠ 闸门被跑过」是本仓栽过的。
所以 `kb/gate.py` ＋ `kb/derive.py` 被挂进了系统的检查引擎：
`backend/checks/kg_citation.py` 注册成 **C4**，`backend/checks/runner.py --all` 里就能看到两行：

    C4.edges      图谱引用可核（路径/行号/符号/值/双源/陈旧）
    C4.instances  图谱实例层（机器派生的楼栋·层）是否对着当前源

跑法（只读，不写 `data/`，也不碰 `qa_structural.py`）：

    python -u backend/checks/runner.py --all            # 全库航拍，含 C4
    python -m backend.checks.kg_citation                # 单独跑这两行
    python -m backend.checks.kg_citation --selftest     # 13 条对照，四个结局各一条

**四个结局各有独立分支，不许合并**（合并就是把「没查成」读成「合格」）：

| 子进程 | C4 结论 |
|---|---|
| 退出码 0 ＋ 能解析出 `fails` | `pass` |
| 退出码非 0 ＋ 报得出红在哪 | `gap`，把失败项逐条列出来 |
| 退出码非 0 ＋ **报不出失败项** | `unavailable` —— ★「红得没有理由」不可下手，比红更糟 |
| 起不来／超时／输出不是 JSON／**④⑤⑥ 某一节说没查成** | `unavailable` —— ★**绝不是 `pass`** |

最后一行值得单说：门禁的 `_fails` 只把 `gap` 收进失败项，所以某一节报 `unavailable`
时它**退出码仍是 0、`fails` 仍是空** —— 屏幕上看和「全查过且全对」一模一样。
C4 专门把这一档拦下来（不改门禁：门禁负责判，C4 负责保证「判过了」是真的）。

**证词里必带尺子指纹**（`gate_sha12` / `values_sha12` / 实例层产物自己的 `self_sha12`
＋ `criterion_version`）以及**边数**：只留 `n_fails` 的话，
「99 条边全核过」和「一条边都没核」在证据里长得一模一样。

**这两条验收判据可以随时重跑**（它们不在 `_scratch/`，不会被搬走）：

    python -m backend.checks.kg_citation_accept --diff       # 进表只多这一行（内存里摘掉 c4 做差分）
    python -m backend.checks.kg_citation_accept --falsify    # 真改坏一条 evidence，再逐字节还原

`--falsify` 改的是 `kb/kb.json`（构建产物），全程备份→改坏→量→还原→`cmp`＋sha12 双验；
★ 它还会**重出一次总表快照** —— 改坏窗口里那次 `runner --all` 会把「C4 是 gap」的红快照
写进 `data/_meta/checks/fleet.json`，不重出的话盘上就躺着一份说现在也是红的假产物。
