# 数字孪生域总览

> 域：`twin`。三域的分工是一条线：`drafting`（读图）问**图上画的是什么**，
> `solid`（成体）问**怎么照图把体建出来**，本域问第三件事：**这份孪生可不可信、凭什么信**。
> 本域**不收几何判据**（那些在 `drafting` / `solid`），也不重复可跑的判据
> （那些登记在 `kb/playbook.json` 的 `runs[]`）。本域收的是**链上的错**。

## 一句话边界

几何对、账本对、名册对，孪生**仍然可能不可信** —— 因为孪生不是一件东西，是**一串派生**。
每一环都是上一环的产物；任何一环陈旧、被覆写，或**被呈现成它上游的样子**，
下游全部安静地错，而且**不报错**（图纸全对、台账全对，看不出链断了）。

## 五段链

```
① 原始 DWG ──► ② DXF ──► ③ profile.json ──► ④ floors/*.json ＋ rooms.json ──► ⑤ <name>-building.glb
   （仓外）      （仓外）      data/buildings/<name>/    同左                      同左
```

★ 只有 ③④⑤ 在仓里。**①② 在仓外**，由环境变量 `GYM3D_DXF_DIR` 指出；本机留空即 B 层跑不了。

## 关键结论

- **孪生 = 五段派生**，而仓里只存了后半截（③④⑤）。派生物与原始图之间**没有链** ——
  这是档案体系要补的第一环，不是疏忽（实测 `data/buildings/c057/` 下一份 `.dxf` 都没有）。
- **界面上那个「原图」不是原图。** `dxf_plan_fast/floor{F}.png` 是本仓渲染出来的 PNG：
  同一份仓的模块 docstring 管它叫「CAD 忠实渲染（原图长什么样）」，
  而 API 常量与前端标签管它叫「**CAD 原图**」。⇒ 「原图 vs 识别结果」这个对拍，
  **左栏不是真值**；两次渲染**共有的**误差在这个对拍里一律不可见（两处一致证明不了它是对的）。
- **新鲜度判据只有一个正确形状**：下游 mtime ≥ 它的**真输入** mtime。
  真输入 = **生成它的那些文件**，不是中间产物。拿中间产物当输入，会把本来有效的产物一律判旧。
- **同一件事在仓里有两套新鲜度口径**：内容指纹 `sha12`（判据的正确形状）
  与 `st_mtime_ns + st_size`（便宜，缓存键在用）。mtime 口径已被实测否掉过一次：
  按 mtime 判模型陈旧**漏了 28/48 栋**，真判据是现码重出比 sha256。
- **陈旧是不出声的**：「这份数是旧尺子量的」和「这份数是对的」在屏幕上一模一样。
  所以链上的判据必须**带尺子指纹 + 时刻**，否则下次读到的数分不清是谁量的。

## 三态（说清「有没有」，而不是给个空数组）

| 态 | 含义 | 不许写成 |
|---|---|---|
| 有 · 新鲜 | 产物在，且比真输入新 | —— |
| 有 · 陈旧 | 产物在，但上游已经变了 | 「有」（会被读成没问题） |
| 无链 | 上游根本不在仓里（①② 在 `GYM3D_DXF_DIR`，本机没配） | 「缺产物」（把它读成这一栋的缺陷） |

★ 第三态是本域特有的：`无链` 是**环境事实**，`缺产物` 是**这一栋的缺陷** ——
两者在界面上长得一样，而处置完全不同（一个是配环境，一个是重修那一栋）。
