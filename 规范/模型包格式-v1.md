# 模型包格式 v1

> 状态：**已定死**（步 1 产出，2026-10-12）。这是①本地建模平台与②服务器平台之间的**唯一接缝**（§6.7.5）。
> **不许随手改**：改这里 = 两个平台同时改；版本号升一档，且旧装载口必须能识别并**明确拒绝**不认识的版本。
> 可执行件：`tools/modelpack.py` · 判据 `gates/J-10.2-01_modelpack.py`。

## 1 包是什么

本地建模平台把一栋楼的产物打成**一个目录**（后续可 zip／tar，但**装载口只认「目录 + manifest.json」这一层**）：

```
<包>/
  manifest.json            包的身份证 + 逐件清单 + 校验和（**字节层写盘**，utf-8 + LF）
  model/ <栋号>-building.glb        几何基线（唯一必需的 role=model）
  ledger/ <栋号>-audit.json         料账（逐层构件数 / 墙长 / 房间数…）
  meta/ profile.json · spec.json    楼栋档案与参数
  qc/ <栋号>-qc.json                ★ 质检报告（**没有它，包装不上**）
```

★ **包里没有原始影像**（§6.1 边界纪律 4）：不装摄影测量、不做切片、不存原片。

## 2 manifest.json 字段（v1 固定）

| 字段 | 类型 | 含义 |
|---|---|---|
| `schema` | str | 固定 `"cdut3d-modelpack/1"` |
| `campus_id` | str | 校区（决策 4：第一天就带，将来加校区不改表） |
| `building_id` | str | 栋号（如 `c006`） |
| `created_at` | str | ISO8601 带时区 |
| `no_raw_imagery` | bool | **必须为 true**；声明包内无原始影像 |
| ★ `lod` | obj | 模型精细度声明（**必填**，见 §2.1）；等级名必须**从标准正本抄**，不许自造 |
| `package_sha256` | str | 对本 manifest 去掉该字段后、`sort_keys` 规范化再 sha256（可复现，不手打） |
| `artifacts[]` | list | `{role, path, bytes, sha256}`；`role ∈ {model, ledger, meta, texture, overlay}` |
| `qc` | obj | `{path, schema, level}` —— 指向质检报告 |

## 2.1 `lod` —— 模型精细度声明（必填）

装载口要知道「我在显示什么等级」，服务器侧才能选渲染路径、决定标称精度。**等级名不许自造**：
必须从标准正本抄，并写清**本包与该等级的适用关系**（是 / 不是 / 超出 / 不适用）。

结构（四个键**都非空**，缺一即拒）：

| 键 | 含义 |
|---|---|
| `standard` | 标准族与出处：`{name, id, issued, tier}` —— 名称/编号/发布期/层级，**抄正本** |
| `level` | 本包声明的等级串（如 `">=LOD1.3"` / `"LOD1.3"` / `"非本族：构件级"`）；**只填正本里真有的等级** |
| `relation` | 一句话说清本包与该等级是**是 / 超出 / 不适用**，以及为什么 |
| `citations` | 引用的质检口径：`{external, national_check, process}` —— 外部质检标准号 + 过程层级 |

★ **cdut3d 现用的那条**（C006 交付包）：国家标准族 = **《实景三维中国建设城市三维模型（LOD1.3 级）
快速构建技术规定（试行）》**（新型基础测绘与实景三维中国建设技术文件—12，2023-09）。
C006 是**构件级白模**（墙/门/梯/电梯/楼板逐层分件），精细度**高于** LOD1.3 的棱柱体体块
⇒ **`level` 写 `">=LOD1.3"` 并注明「超出适用范围」**，**不许**直接写 `LOD2`/`LOD3`
（这两个等级的定义**不在**该规定里 —— 它只定义 LOD1.3 与「高精细度建筑模型」，
分级称见另行发布的《基础地理实体数据成果规范》）。
外部质检口径引 **CH/T 9024-2014**（该规定「引用文件」所列）+ **GB/T 18316-2008**（其参考文献 [4]）。

★ **本规定的平面/高程精度表不套用本包**：那是**卫星立体影像测图**口径（规定自带
「0.5–0.8 m 卫星立体影像可放宽 1 倍」的注），C006 源自**图纸 DXF**（规定五法之一「基于大比例尺
地形图构建三维模型」，引用文件含 CH/T 9009.1-2013 数字线划图）⇒ 精度另按同口径 IoU（真值=DXF）
与尺寸判据度量。**数据格式表**（OBJ/JPG/SHP/XLS）与**元数据 XLS** 是**城市级汇交**口径
（且规定要求「数据单元不得以单个建筑物为单位」），本包是两平台接缝的**中间件**，不是汇交成果。

## 3 质检报告 cdut3d-qc/1（装载口的硬门槛）

| 字段 | 含义 |
|---|---|
| `schema` | 固定 `"cdut3d-qc/1"` |
| `gauge` | `{name, value, threshold, unit}` —— 同口径 IoU（真值=DXF，栅格 50 mm），阈值 0.95 |
| ★ `positive_control` | `{fired, perturbation, value, expect}` —— **`fired` 必须为 true** |
| `level` | `PASS` / `OK` / `WARN` 是合格；其余（含 `FAIL`）不合格 |
| `blind_spots[]` | 这把尺子对哪几类东西看不见（§10.0.1-3） |
| `records[]` | 逐层明细（可含审计原样带过来的字段） |

★ **为什么 `positive_control.fired` 是硬门槛**：一份**没有触发正对照**的质检报告，无法证明它的尺子有分辨力
（§10.0.1-4）。缺它 ⇒ 报告等同没写 ⇒ **包装不上**。

## 4 装载口的硬条件（= `validate()` 的拒绝条件）

合格包必须 **0 条**硬伤，否则拒绝并给出**可数的原因码**：

| 原因码 | 触发 |
|---|---|
| `MANIFEST_MISSING` / `MANIFEST_BAD_JSON` / `SCHEMA_MISMATCH` / `IDENTITY_MISSING` | 无清单 / 解析失败 / 版本不符 / 缺校区栋号 |
| `ARTIFACTS_EMPTY` | 清单为空（**非空断言**：空清单的绿不算绿） |
| `ARTIFACT_MISSING` / `ARTIFACT_SIZE` / `ARTIFACT_SHA` | 件缺 / 字节数不符 / sha256 不符 |
| `NO_MODEL_ARTIFACT` | 没有 `role=model` 的件 |
| `LOD_MISSING` / `LOD_BAD` | 无 `lod` 声明 / `lod` 缺 `standard`·`level`·`relation`·`citations` 之一 |
| `NO_RAW_DECLARATION` / `RAW_IMAGERY_PRESENT` | 未声明无原片 / 包内查到原片 |
| `NO_QC_REPORT` / `QC_BAD_SCHEMA` / `QC_LEVEL_FAIL` / `QC_NO_POSITIVE_CONTROL` / `QC_NO_GAUGE` / `QC_BELOW_THRESHOLD` | 质检报告缺项或不过 |

## 5 量具、正对照与盲区

- **量具**：`tools/modelpack.py::validate()`；单位=原因条数；合格阈值=0。
- **正对照**（`gates/J-10.2-01_modelpack.py`，2026-10-12 实测**全红**）：
  合格包放行 ✔ ｜ level=FAIL 拒 ✔ ｜ 正对照未触发 拒 ✔ ｜ 件改一字节 拒 ✔ ｜ 塞 .jpg 拒 ✔ ｜ 抽掉质检报告 拒 ✔。
- **盲区（否定判词不算证据的地方）**：
  1. 原片只按扩展名／目录名**粗筛**，识别不出「改名叫 `.bin` 的原片」⇒ 权威是 manifest 的 `no_raw_imagery` 声明；
  2. 只校验 manifest **登记过**的件，不告发「包内夹带、未登记的私货」；
  3. 不校验 GLB 内部几何与 DXF 是否一致（那是 §10.1 建模判据的事，不是装载口的事）。

## 6 变更纪律

- 升版只改 `schema` 串；装载口遇到不认识的 `schema` **必须拒绝**，不许「尽量解析」。
- 加字段可以（向后兼容）；**删字段 / 改字段含义必须升版**。
- ★ **2026-10-12 例外备案**：`lod` 是**加严**（由「没有」变「必填」），不是向后兼容的加字段。
  之所以在 v1 内加严而不升版：**v1 只有一个包、没有第二个消费方**（装载口尚未部署）⇒ 无兼容包袱。
  一旦有第二个消费方，任何再加严都必须升版。
