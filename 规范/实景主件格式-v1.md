## 0 一句话

**主件 = 每块取「LOD 前沿」合面成一个 glb ＋ 一份谱系映射表 ＋ 一份台账。**
它**不是**「把这一块的所有 LOD 都合起来」，也**不是**「把整个校区合成一个文件」。

### 0.1 ★ 为什么是「LOD 前沿」而不是「最高的那几片」

瓦片是**平铺**的，LOD 只写在**文件名**里（`Tile_+003_+005_L18_0uuuu0.glb`）；`refine` 实测为 `REPLACE`。

- **取「LOD 最大的那几片」是错的**：实测 `Tile_+003_+005` 最高 LOD=19 **只有 2 片**，
  而 L18 有 **4 片** ⇒ 只取 L19 那 2 片会**丢掉这一块约 7 成面积，而且一声不吭**。
- **按块把 9 层 LOD 全合起来也是错的**：父子重叠 ⇒ z-fighting ＋ 约 9 倍冗余面。
- **正解 = LOD 前沿**：每个分支取它**能取到的最深一片**，即
  「**有 content，且其下没有更深 content**」的那些片。这个集合恰好**无缝、无重叠、且最深**。

实测全库：节点 **48,695**，带 content **48,694**，**前沿 34,740 片 / 124 块**。
前沿深度分布 `{5:1, 6:17, 7:135, 8:1799, 9:25859, 10:6929}`。
★ **割的合法性已验证**：块内每个 content 节点，要么**在前沿里**，要么是**前沿某片的祖先** ——
实测 **0 个孤儿**。

## 1 主件长什么样

一块一副产物，落在 `<out>/<block>/`：

```
<out>/<block>/<block>.glb            主件几何（每片一个子网格，各自贴图）
<out>/<block>/<block>.lineage.json   谱系映射表 + 逐片读数 + 覆盖判据读数
<out>/_index.json                    全批台账（逐块一行 + 汇总 + 判旗）
```

**`<block>` 就是源块的目录名**（如 `Tile_+003_+005`），**逐字照抄，不重命名、不归一化**：
块名是源件的身份，改了就再也对不回源。

### 1.1 主件的坐标框架

| 项 | 定死值 | 依据 |
|---|---|---|
| 朝上轴 | **glTF Y-up**，与源叶件**一致** | 源 `tileset.asset.gltfUpAxis = "Y"`（实测） |
| 是否翻转 | ★ **不做任何翻转** | 主件与源叶件同框架 ⇒ **回切无需逆变换**；少一次变换少一处错 |
| Y-up ↔ ENU | `(x, −z, y)` | ★ **实测**：叶件 bbox 按此式翻转后，与 tileset 里 child0 包围球心吻合 |
| 是否带 `transform` | ★ **不带** | 实测全树**非根带变换 0 个** ⇒ 所有 content glb 共享同一个局部坐标系，直接拼接成立。拆件前有**前置自检**，出现非根变换就**拒绝出件**（`rc=4`） |

★ 这条是**地基的合法性来源**：如果哪天源件改成逐节点带变换，拼接就会静默错位。
所以自检不是装饰，它是本规范成立的前提。

## 2 `<block>.lineage.json` 字段（v1 固定）

| 字段 | 类型 | 含义 |
|---|---|---|
| `schema` | str | 固定 `"cdut3d-reality-master/1"` |
| `block` | str | 块名（＝源目录名） |
| `src_tileset` | obj | 源 tileset 的**身份快照**（见 §2.1） |
| `frame` | obj | `{gltf_up_axis, note}` —— 坐标系声明（§1.1） |
| `n_pieces` | int | **前沿片数**（＝子网格数，除非某片内含多 geometry） |
| `pieces[]` | list | 逐片读数（见 §2.2） |
| `missing_on_disk` | list | ★ **被点名但盘上没有**的片 —— 不许静默跳过 |
| `errors[]` | list | 读不动的片 `{uri, error}` —— 不许静默丢件 |
| `master` | obj | 主件自己（合面后）的读数（见 §2.3） |
| `meta_bbox_declared` | list | `meta.json` 声明的 bbox（**只取来核对，绝不用它取文件名**） |
| `meta_vs_root_delta` | list | ★ **自洽核对**：meta 声明 − 根片，实测应为全 `0` |
| `frontier_vs_root_delta` | list | ★ **LOD 粗细差**：前沿 − 根片。这是**信息量，不是错** |
| `coverage` | obj | ★ **覆盖判据**读数（§3.1） |
| `ok` | bool | 无 `missing` 且无 `errors` |

★★ **三个包围盒读数必须各贴各的标签，不许混成一个「偏差」**：
① `meta_vs_root_delta` 是**自洽核对**（应为 0，不为 0 说明这块的 meta 不可信）；
② `frontier_vs_root_delta` 是 **LOD 粗细差**（实测样例块 5.677 m，**不是错**）；
③ `coverage` 才是**覆盖判据**。
把 ② 说成「独立参照对上/对不上」是错的 —— 它是**同源的粗 LOD 零件**，
而 `meta.bbox` 就是根片 bbox（§4 第 4 条）。**两个同名的量必须死掉一个**（铁律 174）。

### 2.1 `src_tileset` —— 版本快照（跨仓引用的凭据）

必须逐字记下，否则「主件是从哪一版源拆的」事后无法回答：

`asset`（版本 + `gltfUpAxis`）· `geometricError` · **`root_transform`（16 元组，ECEF）** ·
`refine` · 根包围球 · 节点数 · **`tileset.json` 的 sha256**。

★ 实测根变换（**回切必须逐位复现这一串**，见 §5）：
```
[-0.9697593374054485, -0.24406316296185585, 0.0, 0.0,
  0.12446805683156804, -0.49456074753890544, 0.8601844975482484, 0.0,
 -0.20993934920238025, 0.834171948388828, 0.5099829704781008, 0.0,
 -1340277.7298440344, 5325452.753539729, 3233997.763051162, 1.0]
```
平移模长 6.373×10⁶ m ≈ 地球半径 ⇒ **ECEF（EPSG:4978）**；`pyproj` 反算得
**30.662695421°N / 104.126476341°E / h = 422.000 m**，与 `理工模型202408` 的局部原点
`(416281, 3393904, 422)` ＋ EPSG:4544 反算值**逐位相同、水平距 0.000 m**。
★ 更正：此处原稿写「纬度反算 30.5°N」**是手打错的**（并据此写过「两套锚定方式不同」）；
更正后的事实是 —— **两套锚定是同一个原点**，真正不同的是**坐标框架约定**：
瓦片走 **ENU→ECEF**（地心直角＋ENU 基向量），模型走 **4544 投影平面＋椭球高**。
根包围球 `[1769.6996, 1998.5597, 76.3654, r=1680.6832]` · `geometricError = 335.2542532244541`。

### 2.2 `pieces[]` 每片一行

`name` · `uri` · `lod` · `depth` · **`ancestors`（取自树，不取自文件名）** · `bytes` ·
`n_v` · `n_f` · `bounds` · `has_uv` · `texture`。

★ **祖先链必须取自树**。第一版拿文件名前缀判祖先 —— 跨 LOD 时字符串前缀根本接不上
（`..._L14_0u` **不是** `..._L19_0uuuu20` 的前缀），把 13,830 个**正常祖先**误报成孤儿。
**尺子看不见的关系类型必须先声明**（铁律 158）。

### 2.3 `master` 主件读数

`n_geom` / **`n_geom_readback`**（★ 落盘后**重新读回**再数的几何数 —— 写进去 ≠ 写得对）·
`n_v` / `n_f` · `bounds` · `bytes` · **`sha256`** · `n_tex_src` / `n_tex_readback` ·
**`tex_roundtrip`**（见 §3.3）· **`coverage`**（见 §3.1）· `image_restore`（见 §3.3）。

## 3 判据（三条，各自独立，**不许合并**）

### 3.1 ★ 覆盖判据 —— 前沿足迹 vs 根片足迹（栅格法）

**量什么**：把**前沿**与**根片**（同块、**两组不同文件**）各自水平投影到
**同一张 0.25 m 栅格**上，数被盖住的格。
- 格边长 **0.25 m ＝ 现有 `fly2024_dsm_025.tif` 的像素大小**，不是随手取的数。
- 主判据是 **缺格直读**：`根片盖住 ∧ 前沿没盖住` 的格数。**比值说不出的那种失败，缺格说得出来**
  （缺栋的面积会被分给邻居，总量照样平）。
- 辅助判据是**比值离群**（中位 ± 10×MAD，阈值**由本批实测分布算出**，不许手打）。

★★ **本尺子换过三版，前两版都栽过，记录在此以免重犯**：

| 版本 | 做法 | 结局 |
|---|---|---|
| 一 | 逐三角 `shapely.unary_union` | **算对，但跑不动**：真实块 20 万–80 万面，于是加了 20 万面上限 ⇒ **12 块里 8 块「量不到」**。一把对多数样本瞎的尺子等于没有（铁律 158） |
| 二 | `trimesh.path.polygons.projected()` 逐片求轮廓再并 | **能 scale，但是错的**：同一块读出 **0.924513**，而栅格读 **1.000000** ⇒ 它把近垂直立面投成的退化细条交给「投影点三角化后取轮廓」那条路径，**少算 7.5%** |
| 三 | **0.25 m 栅格数格**（本版） | **又对又能 scale**，还顺带产出缺格地图 |

★ 第二版的教训值一条铁律：我拿**平面**人造输入给它做过正对照（10×10 m 正方形、四象限拼满、
每片拆两个三角几何、只铺一半），**四个真值全中** —— 平面输入**没有退化投影**，
所以那把正对照**抓不住这个错**。**「对简单输入正确」证明不了「对复杂输入正确」。**
最终是**第三把算法完全不同**的尺子（栅格 vs 多边形求并）把案子判了。

**★ 这把尺子的分辨率下限**：比值的最小可分辨变化 = `1/根片格数`。
不声明它，栅格只有几百格的小块会被当成离群 —— 实测 `Tile_+004_+004` 全块**只有 324 格（20 m²）**，
比值 1.003096 的偏差**恰好等于**它的分辨率 0.003096，也就是**一格之差**。
⇒ 判离群必须**同时**越过两条线：① 分布线 10×MAD；② **这块自己的分辨率下限**。

**盲区声明**：
1. **边界欠算**：格心落在图形外就不计该格 ⇒ **绝对面积系统性偏小**，量级 ≈ 周长 × 半格边长。
   本判据**只用比值**，两侧在同一张栅格上、共享同一套边界偏差，比值里相消
   ⇒ **比值可信、绝对数只是读数**，两个字段分开印。
2. 对**比一个格还窄**的条（< 0.25 m 的墙线）看不全；该条只在单侧出现时会拉动比值。
3. 只在**水平投影**上说话：立面、悬挑、桥下空洞在投影里被压平 ⇒ **盖住 ≠ 有几何**。

**正对照（必配）**：三类坏输入，每类都必须**报出具体是哪一个**（脚本 `_scratch/_pc_coverage.py`）：

| 类 | 注入 | 必须的读数 | 实测结果 |
|---|---|---|---|
| 丙 | 空白对照（名单不动） | 缺格**恰好 0** | 3/3 块 **0 格** |
| 甲 | **丢一片** | 缺格 > 0，且最大缺块的**位置落在被丢那片自己的水平范围内** | 3/3 块认出：缺 2117/2673/2458 格（132–167 m²），位置逐位吻合 |
| 乙 | 改一名（盘上不存在） | 必须**点名** | 3/3 块点名 |

★★ **甲这一类的危险之处**：丢掉一片之后，**合面照样成功、文件照样写出、大小照样合理** ——
实测三块的 `ok` 全部为 `true`。**没有这把尺子，症状就是「少了一栋楼但一切绿灯」**（铁律 137）。

### 3.2 ★ 前置自检（不过就拒绝出件，`rc=4`）

1. **逐节点 transform**：非根带 `transform` 的节点数必须为 **0**，否则拒绝（§1.1）。
2. **前沿非空、块非空**：前沿为 0 的块必须列出来，否则拒绝。

★ `rc=4` 的语义是「**这把尺子这次量不到**」，**不是**「量到了、合格」。两者不许混。

### 3.3 ★ 贴图往返无损

**量什么**：源叶件的贴图 → 主件 → 读回，**逐像素**比。字段
`max`（最差单像素差，0–255）与 `pct_pixels_differ`（异像素百分比）。

★★ **这一环差点成为地基的一处有损**：实测 trimesh 导出 glb 会把 JPEG **解码又重编码**，
单次往返在样例块上是 `max=10、7.6% 异像素`，**12 块实测最差 max=53、异像素 25%** ——
这不是「差不多」，是**肉眼可见**，且多趟往返会**累积**。

**解法**：trimesh 导出后，把**原始 JPEG 字节换回去**（`restore_glb_images`），
映射按**加几何的顺序**（`sorted(uris)`），**不按像素猜** —— 猜是循环论证。
张数对不上就**一个都不换**（宁可保留有损，也不许错位换）。

**实测（12 块）**：源 **2230 张 → 读回 2230 张**，**每块 `max=0`、异像素 `0.0%`**。
⇒ 规范对使用者承诺的是：**主件的贴图与源件逐字节相同**。

**盲区声明**：本检查只覆盖**贴图像素**。它**看不见** UV 坐标是否被重排、材质绑定是否错位、
法线/金属度等其它贴图通道是否存在。这些项**本版不承诺**。

## 5 回切必须做到的（约束，不是建议）

1. **逐位复现 `root.transform`**（§2.1 那 16 个数）。§6.2.3 纪律 3 要求「新旧瓦片共存、按栋替换」
   ⇒ 新件与旧件**必须叠得上**；平移或旋转差一点，新旧就是两层皮。
2. **重算包围盒**：源件的包围盒**被手工改过**（§4 第 9 条）⇒ 不许照抄，必须现算。
3. **按谱系表回写**：同 LOD 回同 LOD。往返判据**同 LOD 比同 LOD**，
   否则「LOD 差」会被误报成「编辑差」。
4. **不经 OSGB**：`3dtile.exe` 是 **OSGB → 3D Tiles**，而主件是 glb，
   且**全盘没有 OSGB 写出器** ⇒ 回切走 **`py3dtiles 12.1.1`** 直接写 glb 3D Tiles。
5. **容器里不许有原始影像**：仍由 `tools/modelpack.py` 的 `RAW_IMAGERY_PRESENT` / `NO_RAW_DECLARATION` 守。
   实景瓦片**不走模型包通道**。

## 7 不承诺（★ 硬限制，不是没做）

- ★★ **改了几何之后，立面的纹理只能局部可改**：源航测**没有原始影像**（2024 那套不在盘）
  ⇒ 照片烘焙的纹理图集**无法重投影**。屋顶与地面可拿 **0.25 m 的 DOM 重投**；
  **立面只能沿用已烘焙的图集** ⇒ 改动会在立面表现为**拉伸或鬼影**。
  **几何可改，纹理只能局部可改。** 这一条必须写进交付说明，不许讲成「随便改」。
- **不承诺自动单体化干净**：竖切会切掉屋檐/挑台、把穿进轮廓的树冠收进来、贴建楼之间没有可切的缝、
  墙脚与地形交成锯齿。只承诺切出**可指名的栋块**，干净度留给编辑器人工修。
- **不做玻璃/水面自动分流**：纯几何里水面、玻璃、平分不开 ⇒ 明确列为「不做或人工」。
- **不承诺实景精度到 cm**：源是航拍斜视、DSM 0.25 m/px。精度**先量后说**，量不出就只记录。
- **不承诺 UV / 材质绑定不变**（§3.3 盲区）。
- **编辑器不进链**：仓规定死「无 headless 入口的软件必须踢出链，不许在链里留『人工点一下界面』的步骤」。
  编辑器是**交付件**（人用），链上每一步仍必须命令行可跑。
