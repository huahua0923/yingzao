## 0 一句话

**本仓不做这块几何，SU 也不做判断。**
判断（哪两根线是一堵墙、板在哪、门开在哪）在 Python 侧做完；SU 只干它唯一擅长的那件事：

```ruby
f = ge.add_face(pts(rr, zmm))   # 平面内一个闭合环 → 一张面
f.pushpull(amt)                 # 面 → 体
```

⇒ 「上游要交给 SU 什么」这个问题，**等价于**：「`add_face` + `pushpull` 在什么输入上
会不出面、出歪面、或把 SU 转死」—— 逐条答案在 `SU对CAD的数据要求.md`。

### 为什么判断不交给 SU（三条路全部实测过、全部不通）

| 想干什么 | 结果 |
|---|---|
| `add_face(外环, 洞1, 洞2…)` 多环 | 抛 `Not enough edges` / `wrong number of values` |
| `add_edges(洞环, true)` | 抛 `ArgumentError`（旧代码靠 rescue 偷偷回落） |
| `add_face(外环)` 指望它把已有的闭合洞边当洞抠掉 | **不抠**（实测：先画洞边再成面 = 实心 4.00 m²） |

再加上底图双线墙在 SU 里**围不成环** ⇒ 不成面 ⇒ 导 OBJ 只有 **147 字节空件**（实测）。
⇒ 洞挪到 Python 侧切（`export_contours.py::_cut_holes`），进 SU 的环 `holes` **恒 `[]`**。

★ 旧注释「SU 成面时会自动把内部已有的闭合边当洞抠掉」**是错的**，已删。
★ 旧版的 `holes_cut=147` 数的是 `add_edges` **成功次数**、不是抠成的洞
（铁律 158：判词先声明量具对什么盲）—— 那个计数已不再出现、也不再当判据。

## 2 SU 那一步，逐句拆（`su_step2_build.rb`）

### 2.1 进去之前（顺序不能换）

- **启动器**：`_run_su_step2.ps1` 用 `Start-Process` 起，**与本会话控制台解绑**。
  挂着会话控制台起的 GUI 程序，控制台被收走几秒后窗口会收到**外部 `close`**：
  退出码 0、无栈、与「跑得好好的」**同形**（memory: console-teardown-closes-gui-window）。
  ★ 该文件里**一个中文都不沾**，路径全部由 `$PSScriptRoot` 推出来 ——
  Git Bash 传中文 argv 会被改坏（`项目` 变成 `y??v`）。
  ★★ **改这个 `.ps1` 一律写 UTF-8 带 BOM（`utf-8-sig`，字节层写盘）**。2026-10-16 实测踩过：
  写成 **UTF-8 无 BOM** ⇒ PowerShell 5.1 **当 GBK 解**，中文串的字节**把换行吞掉**
  （`wc -l` 39 行 vs `(Get-Content x.ps1).Count` 25 行），被吞的 `$skp = …` 落进注释成 `$null`，
  报错却指向 `Test-Path : 无法绑定参数…该参数为空值`。改完**对一遍行数**再跑。
- **起始文档用 `c006_su_1f.skp`（664,305 B），不要用 `c006_su.skp`** ——
  后者是**上一趟的输出件**（7.40 MB），拿它起 = 每次启动先吞整个成品；
  输出存到哪由 `su_step2_build.rb:147` 定，**与起始文档无关**。—— 2026-10-16 改。
- **必须给一个「已存在的 `.skp`」参数**，否则欢迎屏挡住启动、脚本一行不跑（`-RubyStartup` 本身是好的）。
- ★ **`rc=0xC0000374`（`STATUS_HEAP_CORRUPTION`，`ntdll.dll`）是这条路上的间歇崩**：
  同一份载荷**崩 4 趟 / 过 3 趟**，崩时日志一行不写。别当场改几何 ——
  处置 = 挪走**陈旧同名 `.skb`** ＋ 用**小文档**起。★ 崩了与「没进去」症状同形，判词要分开（铁律 199）。
- **先杀净 SketchUp 并无条件等 ≥5 s**。SU 是**单实例**：旧实例还没退干净就再启一个，
  新实例把参数静默交给旧的然后自己退出 —— **脚本一行不跑、零报错、rc=0、日志零行**。
  ★ `(Get-Process SketchUp).Count == 0` **不能证明可以启动了**（实测第一轮就返回 0，立刻启 ⇒ 照样撞上）。
- 判「这趟进没进去」**只认日志里新的 `SCRIPT_ENTERED` 行**。
- **单位**：Ruby API 里**裸数字一律是英寸**，一律 `.mm` 换算。写错的后果不是报错，是
  整栋 **×25.4**（实测 10000×8000×4000 被建出 254000×203200×101600 mm）。
  菜单里的 `UnitsOptions/LengthUnit=2`（毫米）**只管显示**，管不了 API 里的数字。
- **层高**：`ALL_FLOORS` **现读 `contours/index.json`** 的 `floor / z0_m / h_m`，**不写死**。
  写死在这里的后果不是「慢」，是**静默**：环按 A 米一条条出、脚本按 B 米摆层 ⇒
  每层错 `(B−A)·k` 米、顶层错 `(B−A)·N` 米，而面数照样对得上、**没有任何一条判据看得出来**
  （铁律 018/174：同一个量两个估计器）。★ 本条**不举具体数** —— 层高是**口径决定**，
  2026-10-15 曾令 3.5 m、2026-10-16 用户裁定「按甲定案 · 重算整条链」回 **4.0 m**；
  哪个数当例子都会过期，而写死的那个会悄悄留在件里。读不到 `index.json` 就**抛异常停**，不猜。

### 2.2 分三批建，每批每层一个原子操作

| 批 | 类 | 为什么这么排 |
|---|---|---|
| 批1 | `DOOR` | ★ **门放第一个**：实测门批连挂两趟，两趟都停在同形状处（CPU 满转、窗口不响应 ⇒ **是在算**，不是死锁，也不是脚本异常）；而门本身一字未改（2 层 312/312、4 层 304/304 环与上一趟逐字节相同）⇒ 变量只有一个：**建门时文档里已经躺着四千多张墙面** |
| 批2 | `WALL COL LIFT SLAB LINTEL PARAPET ROOF_STAIR ROOF_STEP ROOF` | 通层高的主体件 ＋ 顶部四件（2026-10-15 起含 `ROOF` 塔楼屋面板） |
| 批3 | `STAIR` | 量最大（1 层 512 条） |

- 分批不是「为了快」，是**规模**：一次塞 8 570 张面 ⇒ SU 中途异常终止 **`rc=127`**，
  两次死在**不同位置** ⇒ 是规模性问题，不是某条多边形有毒。
- 每批之间 `model.save` 一次（后面某批崩了，前面几批不用重跑）。
- ★ **批次次序不改变成品形状**（同层同类各占一个组），它只改变「建门时文档里有几张面」。

### 2.3 每一步在干什么

1. `model.entities.erase_entities(to_a)` —— **每次都是重来**（洞的修法变过，旧件里的实心墙必须全丢）。
2. 逐层逐类建一个 `Group`，组名 `"<层>_<类>"`；**同名组已存在就跳过**。
   —— 这条「跳过」是它当年**能分批**的原因，也是为什么补救要另一个脚本
   （`su_fix_erase.rb`，删的名单从 `_erase.txt` 读、**不写死在脚本里**，免得补救代码将来变地雷）。
3. 逐块：`clean_ring` → `add_face` → `pushpull`。
   - `clean_ring`：**成面之前先洗环**。contours 里的 ring 是 shapely 的闭合坐标串，
     首点被原样又写了一遍 ⇒ 直接喂 `add_face` 会造一条**零长边**，SU 在 pushpull 愈合零长边时
     **会自旋**（实测：6 层 DOOR 第 6 个组把 SU 转死、CPU 稳定 ~93%、日志停在那一行）。
   - **拉伸高度逐块优先**：`pr["h"]` 有就用它（楼梯每级要从自己的底标高长到**自己那一级**，
     否则还是薄板不是踏步），没有就退回该类的层常数 `push_mm[layer]`。
4. **自检写日志**（不猜）：`FACES built=… fail=… 退化环=… floor_skipped=…`、`BBOX_mm size=…`、
   逐层逐类面数（应与 `contours/index.json` 的条数对账；对不上就是漏建）。
   - `FACES fail` 多了 = 这趟白跑；`BBOX_mm` 单位错会量出 129300 × 25.4 倍。
5. 存 `.skp` → 导 `.obj` → `DONE` → 3 s 后自己 `quit`。
   ★ **只出 OBJ，不再出 `.dae`**：实测全仓无人读（`grep -rn "\.dae"` 只剩 `daemon_threads`
   这类假命中与注释），而它 32.5 MB/趟、约 1 分钟。代价：哪天要用 DAE 交换格式得把那一行加回来。

### 2.4 怎么判这一趟**跑完了**（★ 别信文件在不在、多大）

- 半截的导出件**仍然「像个文件」**：实测导出中 `.obj` 已 5 302 081 字节、看着正常，
  真值是 13 310 958 —— 中途 `Stop-Process` 就**静默截断**（没有报错、没有 0 字节）。
- 只认日志三句：新的 `SCRIPT_ENTERED`（进去了）＋ `EXPORT obj ok=true` ＋ `DONE`（跑完了）。
  （铁律 199：崩了与没量到不许同形。）
- ★ `model.export` 会**泵消息循环** ⇒ 那个 5 s 计时器在导出**进行中**又触发一次，
  日志里出现 `REENTRY_BLOCKED run=2` **不代表这趟跑完了**（它插在 `SAVED` 与 `EXPORT` 之间）。
- 计时器还有一条历史坑：`UI.start_timer(5.0, false)` 号称「只跑一次」实测**重复触发**，
  一个进程里 `guarded()` 连跑 4~7 遍、内存涨到 1.26 GB、导出的 obj 是 0 字节。
  ⇒ 不去猜这个 API 的语义，直接上**标志位**让重入不可能。

## 3 同一个东西，四层名字（混了就对不上账）

| 层 | 形如 | 出处 |
|---|---|---|
| SU 里的组名 | `<层>_<类>`，如 `1层_WALL` | `su_step2_build.rb:172` |
| OBJ 里的 `g` 行 | `g <MeshN> <组名> Model`，组名**非 ASCII 被 SU 剥掉** | 实测 |
| 台账里的块 | `F01-WALL-001` / `1层-墙块-001` | `contours/<层>.json::polys[].id / name` |
| 交付包里的件 | `packs/cdut-main/c006/…` | `demo/build_pack.py` |

★★ **组名字形实测不统一 —— 这条本仓还没量到根因，别按字形猜**：
同一份件里既有 `__1__DOOR`、又有 `G_1__DOOR`（`su_step2_build.rb:167` 的注释声明的是
「楼上 `G_5__WALL`、地下室 `__1__WALL`」，与实测**对不上**）。
⇒ 要按组筛件（如 `render_box_blender.py` 的 `only=`）：**按类名匹配**（`DOOR` / `LINTEL` /
`STAIR` / `LIFT`），**层由盒子的范围定**，别猜前缀也别猜层号。

★ **`g` 行数 ≠ 组数，也 ≠ 环数** —— **2026-10-15 实测把这条量出来了**（原先写「切法本仓没量过」）：
`g Mesh<N> <组名> Model` 的 `N` 在整份文件里**连续 1…3550**、每个 N 恰好一行，`<组名>` 就是
`su_step2_build.rb` 建的 `(层,类)` 桶名。本趟 **`g` 行 3550 / 不同组名 88**（= 12 层 × 各自到得了的类），
而 **Blender 拆出的对象数也是 3550**（两把互不同源的尺子各数一次，相等）。
★ 同一趟喂进去的是 **8683 条环**（SU 日志 `FACES built=`，`mk_catalog` 的合计同值）⇒ **3550 ≠ 8683**：
SU 导出时把同一组里的若干张面并成了更少的 mesh。**这个合并的分母本仓没量过**，只量到了两个数。
⇒ 判「导出没被截」就用 **`g` 行数 == Blender 拆出的对象数**（同一批件的两把尺子），
**不要**拿 `g` 数去对环数。
★ `COL` 是唯一**三处读数恰好相等**的类（`g` 计数逐层 44/201/197/197/197/178/178/30/22/22/22/22
= **1310** = `构件清单.md §2` 的 DXF 柱块数逐层 12/12）；**别把这一类的巧合推广到别的类**。

## 5 一句话的契约

**上游交给 SU 的**：`contours/<层名>.json` ——
每层 `units` ＋ `push_mm`（**十一类**层常数）＋ `polys[]`：
`layer` / `z`（**相对本层底面**，mm）/ `ring`（闭合、**无洞**、无零长边）/
`holes`（**恒 `[]`**）/ `id` / `name`。

**SU 还给下游的**：`c006_su.skp` ＋ `c006_su.obj`。
★ 朝向与单位**以 `EXPORT.md` 记的为准，别信记忆** —— 同一个 SU 2023 的 OBJ 导出器
本仓量到过 `millimeters`，gym3d 那条链量到过 `inches`（还得在 Blender 里 `global_scale=0.0254`）。
**两次都是真的**，差别只在当时的导出设置。这一行省掉，下游只能猜，而猜错是 **25.4 倍**。
