# three.js 在本系统能做什么 —— 逐条对着现有代码/数据说

> 2026-10-20。用户问「three.js 你能用它来和这个系统做点什么」。本文按**现有资产**分类：
> A 类 = 数据已经有了，只改渲染层；B 类 = 要新数据，但来源在盘上；C 类 = 不该做（说清为什么）。

## 0. 现状：three.js 不是「要不要用」，是**已经在用**

| 位置 | 已经在做 |
|---|---|
| `demo/index.html` | 模块级 three.js：读 GLB（0.9–24 MB/栋）、按 `floorN` / `__ROOF` / `PARAPET` 节点分族、`applyVisibility()` 控制显示、`setWallsTransparent()` 墙体半透明、按 `baseline/floors/*.json` 的多边形现铺房间色块（`ShapeGeometry`）、`Raycaster` 点房间出信息、握手口 `__cdut3d`（phase/pack/tris/kids/layers/buildToken/setPurpose/purposeNow） |
| `demo/building.html` | 外壳：房间台账面板、用途图例（现按图层筛选）、楼层条、与子页握手同步 |
| `packs/cdut-main/<bid>/` | 67 个包：`model/*.glb` + `baseline/floors/*.json`（房间/墙/门/柱平面）+ `ledger/rooms.json`（台账） |
| `rebuild/<bid>/06_su/contours/*.json` | 逐层构件轮廓（`WALL/DOOR/LINTEL/SLAB/ROOF/PARAPET/STAIR`，带 `F05-WALL-001` 这类 id） |

## A 类：数据已有，只改渲染层

### A1. 剖切面（clipping plane）—— ✅ 2026-10-20 已做（用户「可以，你做吧」）

> 落地位置：`demo/index.html` 的 `CLIP_PLANE` / `applyClipping` / `setClip` / `setClipHeight`
> 与探针 `window.__cdutClip`；父页 `demo/building.html` 的「剖切」按钮 + 滑杆（只转发，不另算）。
> 量法：滑杆 0..1000 映射到**该件包围盒** `[最低点, 最高点]`，标签印绝对标高；
> 实测 c005 拖到 430‰ ⇒ `≤ 10.2 m`，截图上 10.2 m 以上整段消失、2/3 层房间色块全露出来。
> 非 embed（四条闸打开的那条路）**不建这个控件**，`clipOn` 恒为 false ⇒ 闸看到的场景不变。


- 做法：`renderer.localClippingEnabled = true`，一层 `THREE.Plane` 挂到所有材质上，滑杆改 `plane.constant`。
- 为什么值：**用户的原话是「不要穿模、不要没有门、不要没有屋顶」**。这三个缺陷在整栋轴测图里都看不清，
  剖开就立刻现形：剖到某一层，把剖切面高度对到同层 DXF 轮廓（`contours/<层>.json`）上，
  与「对照」页那张 2D 叠图**同高一刀** —— 墙带对不对、门洞有没有打穿、楼板有没有盖，一眼到底。
- 成本：约 0.5–1 天。不需要改数据。

### A2. 按层按需加载（性能）
- 现状：整栋 GLB 一次进（c006 已 11.8 MB，c001 19.5 MB，67 栋全开会爆）。
- 做法：装包时按 `floorN` 把 GLB 切成 `<bid>-f<k>.glb`，首屏只加载选中层 + 上下各一层；
  或退一步用 meshopt/draco 压一次（不改结构、当天见效）。
- 成本：切包 1 天（要改 `build_pack_bid.py` 与查看器装载逻辑）；压缩半天。

### A3. 构件级点选 + 缺陷定位
- 现状：只能点房间（色块）。墙/门/柱是 GLB 里的一堆三角面，点了不知道是哪一件。
- 做法：装包时把每个构件写成**独立节点**（名字就用 contours 里已有的 `F05-WALL-001`），
  点中就报：类、层、图纸编号、复核判据（D-04 门扇离墙 / D-11 零门 等）。
  `defect_scan.py` 的 `findings` 里本来就有 `@[x, y]` 坐标 ⇒ 可以**从缺陷跳到三维位置**。
- 成本：1 天（要动装包口径，改完必须重跑一遍全链验证）。

### A4. 量距 / 量高
- 做法：`Raycaster` 取两点（吸附到最近的顶点/墙中线），画线并印米数。
- 为什么值：D-13「墙厚按栋取 240」这类问题，最后还是要人眼量一条墙；在三维里量得比回 CAD 快。
- 成本：1 天。

### A5. 门洞通透性自动检测（把 D-03 从「未量到」变成「已量」）
- 现状：`defect_scan.py` 里 D-03「透明才看得见（门洞没打穿）」是 **检测器缺失**。
- 做法：从每个房间中心向相邻房间中心发一条射线，穿过门洞位置；
  若命中墙三角面 ⇒ 门洞没打穿（红）。这正是现在要人肉开半透明才能发现的那一类。
- 成本：2 天（要写测地/邻接逻辑，可与三维渲染解耦，纯几何）。

### A6. 楼层炸开 / 单层聚焦
- 现状：已有单层显示（`solo`），屋顶会跟着隐藏。
- 做法：加一个「炸开」滑杆（每层沿 y 抬 `k×Δ`），看内部空不空、楼梯接没接上。
- 成本：半天。

### A7. 显示口径切换（颜色含义）
- 现状：按用途上色（今天刚补了「源图无用途 ⇒ 按房间号分色」的兜底）。
- 可加：按面积档 / 按构件类别 / 按缺陷级别着色（红黄提示直接铺到构件上）。成本：按天算不到一天。

## C 类：不建议做（写清理由，免得下次又提）

1. **在三维里改几何**（拖墙、开门洞）。件必须可回溯到图纸，编辑要回 CAD/SU；
   在渲染层改会让「件 = 图纸」这条链断掉，所有判据同时失效。
2. **实时全局光照 / 路径追踪**。看起来漂亮，但与任何一条判据无关，还拖慢首屏。
3. **用 three.js 做 DXF 解析/平面识别**。那条链在 Python 侧（`rebuild/tools/*.py`），
   两边各写一套必然漂（铁律 018）。

## 建议顺序

1. **A1 剖切面**（0.5–1 天，最能替用户看出「做没做完整」）
2. **A2 压缩/按层加载**（0.5 天，67 栋才可能一页看全）
3. **A3 构件点选 + 缺陷跳转**（1 天，把 `defect_scan` 的读数变成可点的东西）
4. **A5 门洞通透性检测**（2 天，补上唯一缺的自动检测器）
5. **B1/B2 实景叠加**（2–3 天，需要先给每栋打 E/N 锚点）
